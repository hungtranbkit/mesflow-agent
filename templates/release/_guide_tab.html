Đẩy sang Production Test

Thao tác 100% trên máy DEV này — không bao giờ vào máy Production Test tự bấm gì. Bấm Promote to Test ở tab Release & Deploy, Agent DEV tự upload + gọi deploy trên Agent của máy Test.

{% if not guide_test_target_configured %}

Chưa có thì nút "Promote to Test" sẽ luôn bị mờ với lý do "No Production Test Agent is configured". Cách cấu hình — chỉ set qua biến môi trường của chính container này, không có form nào trên giao diện lưu được 3 giá trị này (cố ý, tránh lộ mật khẩu qua log/API):

# trên máy DEV (máy đang chạy Agent này) sudo tee -a /opt/mesflow-deploy-agent/docker/.env <<'EOF' MESFLOW_PRODUCTION_TEST_AGENT_URL=https://<domain-hoặc-ip>:8090 MESFLOW_PRODUCTION_TEST_AGENT_USER=<user đăng nhập Agent trên máy Test> MESFLOW_PRODUCTION_TEST_AGENT_PASSWORD=<mật khẩu> EOF cd /opt/mesflow-deploy-agent/docker docker compose -f compose.linux.yml -f compose.dev.override.yml -f compose.bootstrap.override.yml up -d
{% endif %}
  1. Build + Deploy Local

    Ở tab Release & Deploy, bấm Build Release rồi Deploy Local cho version cần đẩy.

  2. Chờ LOCAL_PASS

    Tự động chạy sau Deploy Local: kiểm image id + schema + smoke test, với version ≥70 còn tự gọi QA Center chạy thêm "release-local" evidence. Badge LOCAL chuyển PASS mới đủ điều kiện.

  3. Bấm "Promote to Test"

    Chỉ hiện đủ điều kiện khi LOCAL_PASS + đã cấu hình target ở trên. DEV Agent tự kiểm máy Test đúng SERVER_ROLE=PRODUCTION_TEST và build_enabled=false trước khi đẩy — sai vai trò sẽ bị từ chối, không đẩy nhầm.

  4. Xác nhận TEST_PASS

    Badge TEST chuyển PASS sau khi Agent verify health/version trên máy Test xong.

QA Center dùng chung đúng 3 biến này để promote sang Production Test — không cần cấu hình riêng.

Đẩy sang Production

Luôn cần người bấm xác nhận riêng, mỗi lần — không có luồng tự động nào bỏ qua bước này.

Target Production: {% if guide_prod_target_configured %}ĐÃ CẤU HÌNH{{guide_prod_target_url}}{% else %}CHƯA CẤU HÌNH{% endif %}
Cho phép promote Production (MESFLOW_PRODUCTION_PROMOTE_ENABLED): {% if guide_prod_promote_enabled %}BẬT{% else %}TẮT{% endif %}

Điều kiện đầy đủ: LOCAL_PASS + TEST_PASS + ZIP SHA/image digest/schema khớp + không bị đánh dấu CONTAMINATED + MESFLOW_PRODUCTION_PROMOTE_ENABLED=1 trên Agent này + body request có {"confirm": true} tường minh mỗi lần bấm.

QA Center — build/deploy

QA Center chỉ build; Deploy Agent chịu deploy. Hai đường có thể bấm build:

  • Ngay trong chính QA Center — trang "Release Package" (chỉ hiện khi chạy trực tiếp từ workspace, không có trong image đã đóng gói).
  • Ngay ở đây — thẻ QA Center bên trong tab Release & Deploy, nút "Build Release".

Cả hai gọi cùng một qa-center/scripts/build-release.sh — không có bản build song song. Version đã đóng băng thì build lại sẽ báo lỗi VERSION_ALREADY_RELEASED — không phải bug, tăng version (qa-center/current/VERSION + APP_VERSION trong agent.py, hai chỗ phải khớp nhau) rồi build lại.

Sự cố đã gặp

Deploy Agent local bị lặng lẽ đổi DEV → PRODUCTION_TEST

Triệu chứng: mọi nút Build/Deploy Local mờ, "No release has been built yet" dù artifact có thật.

Gốc rễ: installer hardcode override cho máy mới, quên cộng thêm compose.dev.override.yml khi cài lại trên chính máy DEV — đã fix, installer giờ tự nhận diện.

Kiểm tra nhanh sau mỗi lần Bootstrap cài/update Agent: xem badge vai trò ở thẻ "Vai trò Agent này" phía trên.
